# 写作指南（二）：Markdown 基础语法

本站支持标准的 Markdown（GFM 风格）。这一篇把写文章常用的语法过一遍，每段都配了写法和效果，可以在编辑器里照着敲一遍找感觉。

## 标题

正文里用 `#` 写标题，一个 `#` 是一级，最多到六级。一篇文章通常一个一级标题（就是文章标题），正文里从 `##` 用起：

```markdown
## 二级标题（章节）
### 三级标题（小节）
#### 四级标题（很少用到）
```

## 段落与换行

空一行 = 新段落。**只回车一次也会换行**——本站开启了这个模式，写诗、写短句的时候直接回车就能换行，不用在行尾加空格：

```markdown
樱花落在肩上
也落在未写完的信上
```

上面两行在页面里就是两行，中间没有空行隔开。

## 强调

```markdown
**粗体**　*斜体*　~~删除线~~　`行内代码`
```

**粗体**　*斜体*　~~删除线~~　`行内代码`

行内代码用来包命令、文件名、字段名，比如 `python build.py`、`draft: true`。它自带底色框，是正文里最常用的强调方式。

## 列表

无序列表用 `-`，有序列表用数字，嵌套就缩进两个空格：

```markdown
- 樱花
  - 三月开
    - 四月落
- 自行车
- 自动贩卖机

1. 写下标题
2. 填好信息头
3. 推送，剩下的交给风
```

**任务列表**适合当写作清单，发布后是带勾选框的样子（仅展示，不可点击）：

```markdown
- [x] 选好封面图
- [x] 写完正文
- [ ] 校对错别字
```

## 引用

用 `>` 开头。适合放摘句、旁白、或者自言自语：

```markdown
> 「我们仰望着同一片樱花，写着各自的故事。」
```

> 「我们仰望着同一片樱花，写着各自的故事。」

引用里也可以继续用 Markdown（比如再放个粗体或链接），每行开头都带上 `>` 就行。

## 链接与自动识别

```markdown
[显示的文字](https://example.com)
https://github.com 会自动变成可点的链接
```

链接在新标签页打开。直接粘贴的网址不用包也能点。

## 图片

```markdown
![巷口的自行车](posts/午后散步/street.jpg)
```

`[]` 里的文字是图片的替代描述，图片加载失败时会显示它。路径规则在写作指南（一）里讲过：从站点根出发，`posts/…` 或 `assets/…` 开头，外链直接贴网址。

## 代码块

三个反引号开头和结尾，开头那行后面可以标注语言：

````markdown
```python
print("你好，樱花街道")
```
````

```python
print("你好，樱花街道")
```

本站的代码块是等宽排版、不做语法高亮，但保留了缩进和空行，贴配置、贴命令、贴短代码都没问题。

## 表格

竖线分列、第二行写对齐方式（`:-` 左对齐、`:-:` 居中、`-:` 右对齐）：

```markdown
| 字段   | 必填 | 说明         |
| ------ | :--: | ----------- |
| title  |  是  | 文章标题     |
| tags   |  否  | 逗号分隔     |
```

| 字段   | 必填 | 说明     |
| ------ | :--: | -------- |
| title  |  是  | 文章标题 |
| tags   |  否  | 逗号分隔 |

每一行要写在同一行里，别回车折行，否则表格会断开。

## 分割线与转义

三个以上的 `-` 单独一行是分割线。想让 `*`、`#`、`~~` 这些符号**原样显示**而不是被解析，在前面加反斜杠 `\`，或者干脆包进行内代码里：

```markdown
\*这不是斜体\*
```

\*这不是斜体\*
