# 写作指南（一）：元信息、图片与草稿

这一篇讲的是文章的「外壳」：一个 `.md` 文件从放进 `posts/` 到出现在网站上，中间有哪些约定。正文里的各种排版写法在第二篇，进阶技巧和避坑在第三篇。

## 一篇文章长什么样

每篇文章就是 `posts/` 文件夹里的一个 Markdown 文件，由两部分组成：**信息头（front matter）**和**正文**，中间用一行 `---` 分隔：

````markdown
---
title: 我的第 N 篇手记
date: 2026-09-13
tags: 随笔, 生活
excerpt: 摘要写一句话就行，会显示在首页卡片上。
cover:
draft: false
---

正文从分隔线下面开始，想写什么写什么。
````

信息头看起来像配置，其实非常宽松：**除了 title 都可以留空甚至整行删掉**，文章照样能发布。

## front matter 字段速查

| 字段 | 作用 | 不写会怎样 |
| --- | --- | --- |
| title | 文章标题 | 取正文第一个 `# 标题`，再不行用文件名 |
| date | 发布日期，`YYYY-MM-DD` | 取文件名开头的日期，再不行取今天 |
| tags | 标签，**逗号分隔**（`随笔, 动漫`） | 没有标签 |
| excerpt | 摘要，显示在首页卡片上 | 卡片上不显示摘要 |
| cover | 文章页头图链接 | 用全站默认背景 |
| draft | `true` 即草稿 | 当作正式文章发布 |

两个容易忽略的点：

- **tags 是逗号分隔的字符串**，不要写成列表语法，多个标签之间用英文或中文逗号都行
- **excerpt 留空就真的不显示**，不会自动截取正文；首页卡片上没有摘要那一行，只有标题和日期

## 两种文章形式

**单文件**——大多数文章用它就够了：

```
posts/2026-09-13-我的手记.md
```

**文件夹**——图片多的时候用，把图片和文章放在一起：

```
posts/午后散步/
├── index.md        ← 文章本体
├── street.jpg      ← 配图
└── vending.jpg     ← 配图
```

两种形式对网站来说都是一篇文章，随意切换。文件名建议用「日期-标题」开头（文件夹形式随意），构建脚本会从这里推断日期兜底。

## 图片怎么插

Markdown 插图语法是 `![描述](路径)`，关键在于**路径怎么写**。本站的文章页在站点根目录，所以图片路径要写成**从站点根出发**的形式：

```markdown
![巷口的自行车](posts/午后散步/street.jpg)
![远处的高山](assets/img/mountain.jpg)
![网络图片](https://example.com/sakura.png)
```

三条规则记一下：

1. 图片放在 `posts/` 文件夹里（和文章同级或文章自己的文件夹里），路径就写 `posts/…` 开头
2. 放在 `assets/` 里也行，写 `assets/…` 开头
3. 外链图直接贴完整网址

⚠️ 路径是**区分大小写**的（部署在 GitHub Pages 的 Linux 服务器上），`Street.jpg` 和 `street.jpg` 是两个文件，写错一个字母图就裂了。

`cover` 字段的值也遵循同样的规则，它会把文章页顶部的头图区域换成你指定的图。

## 草稿：写一半的文章先藏起来

front matter 里加一行 `draft: true`，这篇文章就成了草稿：

- 本地预览时**看得见**，列表里带一个金色「草稿」标记，可以随时点开继续写
- 推送到 GitHub 后，部署构建会自动把它剔除——**线上完全找不到它**：列表没有、RSS 没有、正文文件也不存在，访客连猜 URL 都访问不到

写完想发布？把 `draft` 改回 `false`（或删掉这一行）再推送就行。配合编辑器的「草稿」开关，一次点击搞定。

## 创建文章的三种方式

1. **樱笺编辑器**（推荐）：「新建文章」填个标题，形式选单文件或文件夹，front matter 自动生成
2. **命令行**：`python build.py --new 文章标题`
3. **手动**：在 `posts/` 里照着上面的样子建一个 `.md` 文件

最后提醒一句：新建、删除文章之后，`posts.json` 索引需要重建一次——编辑器会自动做；手动操作的话跑一遍 `python build.py`，然后本地预览刷新就能看到。
