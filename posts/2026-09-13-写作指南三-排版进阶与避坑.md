# 写作指南（三）：排版进阶与避坑

基础语法在写作指南（二）里过完了。这一篇讲怎么组合出更舒服的排版，哪些写法本站暂时不支持，以及几个高频问题的速查表。

## 组合玩法：块可以互相嵌套

Markdown 的块级元素可以互相嵌套，组合起来才有排版感。

**引用里放代码块或列表**——引用符 `>` 后面保持缩进：

````markdown
> 配置文件长这样：
>
> ```yaml
> tags: 随笔, 动漫
> draft: false
> ```
>
> - 字段都可以留空
> - 保存刷新即可生效
````

> 配置文件长这样：
>
> ```yaml
> tags: 随笔, 动漫
> draft: false
> ```
>
> - 字段都可以留空
> - 保存刷新即可生效

**列表项里放图片或代码块**——子内容缩进对齐文字开头：

````markdown
1. 先放一张图

   ![巷口](posts/午后散步/street.jpg)

2. 再补一句说明
````

关键细节：**列表项和它的子内容之间空一行**，子内容的缩进要和列表项文字对齐（无序列表缩 2 格，有序列表缩 3 格），这样才不会被当成新段落打断列表。

## 长文的结构建议

- **一个一级标题就好**：文章标题信息头里已经有 `title` 了，正文顶部的 `# 标题` 是给「无 title 兜底」用的，两者别重复写两遍
- **章节用 `##`，小节用 `###`**：层级稳定，目录感和阅读节奏都会好很多
- **excerpt 认真写**：它是首页卡片上唯一的摘要位，一句话点出文章最值钱的部分
- **一段不超过三四行**：网页阅读是扫读，长段拆短、该列表就列表
- **图文交替**：连续文字超过三四屏时，插一张配图当「呼吸点」

## 嵌入视频

**B站视频**（推荐，不占自己仓库空间）：视频页点「分享 → 嵌入代码」，把 iframe 整行粘进文章，前后各空一行：

```html
<iframe src="https://player.bilibili.com/player.html?bvid=BV1GUDdYLE5S&p=1&high_quality=1" scrolling="no" border="0" frameborder="no" framespacing="0" allowfullscreen="true"></iframe>
```

小技巧：把分享代码里的 `//player.bilibili.com` 改成 `https://player.bilibili.com` 更稳；不想显示弹幕可以再加 `&danmaku=0`。本站会自动把嵌入的视频铺满文章宽度、按 16:9 圆角显示。

**本地视频文件**：

```html
<video controls preload="metadata" src="assets/video/demo.mp4"></video>
```

同样自动全宽圆角显示。视频文件建议压缩到几 MB 再放进 `assets/`——GitHub 单文件上限 100MB，仓库也最好保持精简。

## 本站暂不支持的写法

诚实清单，免得你在编辑器预览里看到效果、发布后却发现线上不一样：

| 写法 | 编辑器预览 | 线上文章页 |
| --- | --- | --- |
| `:::note` 提示块 | 渲染成彩色提示块 | 显示为普通文本 |
| `$公式$` 数学公式 | 渲染成公式 | 原样显示 |
| `:spoiler[剧透]` | 可折叠 | 原样显示 |
| 脚注 `[^1]` | — | 原样显示 |

这些是编辑器预览器的扩展能力，博客线上使用的是更精简的渲染器。想要类似效果，可以用「引用 + 粗体」模拟提示块，够用也好读。

另外，HTML 标签大部分能透传，但**不推荐**在文章里写 HTML——样式不受主题控制，还容易把排版撑坏。

## 高频问题速查

**图裂了？**
路径没写对。检查三点：是不是从站点根出发（`posts/…`、`assets/…`）；大小写是否完全一致；文件夹文章的图片是不是放在了那个文件夹里。外链图则检查防盗链——有些图床不允许外站引用。

**表格断开了？**
表格的每一行（含分隔行）必须各自单独一行，中间不能回车折行；单元格想放竖线字符要写成 `\|`。

**列表突然断了？**
八成是列表项和子内容之间忘了空行，或者缩进不对齐。无序列表缩 2 格、有序列表缩 3 格。

**行尾多了个换行？**
本站「一回车即换行」，写正文段落时别随手在行尾回车；想分段请空一行。

**改动没生效？**
- 新建 / 删除了文章 → 需要重建 `posts.json`（编辑器会自动做，手动跑 `python build.py`）
- 改了 `config.js` → 浏览器可能缓存了旧文件，Ctrl+F5 强刷
- 线上没变 → 确认推送成功了，去仓库的 Actions 页看部署是否跑完

## 写完之后的标准流程

1. 本地预览（编辑器点「启动本地预览」，或 `python build.py` + `python -m http.server 8000`）通读一遍
2. 没写完？`draft: true` 先放着，草稿只在本地可见
3. 写完推送，GitHub Actions 自动构建发布，一两分钟后线上可见
